# 少儿编程教学设计与题目规划

> 更新：本文保留前一版代码片段与题型规划；其中行号和摘要属于当时快照。明日课堂请使用 [当前学生练习](classroom/学生练习.md) 与独立教师答案，按函数名查找现行代码。

基于 2026-10-01 的地面足球 B 方案版本。本文完成学习路线、现有代码片段提炼和 15 题蓝图；不是已排版的学生试卷。本轮不改游戏代码，不制作完整题库或学生留白版。

学生年龄和 Python 熟练度尚未指定，因此按“会变量与 if → 会循环与函数 → 能理解状态与二维运动”分层，不把所有数学和类的知识都设为前置要求。

## 一、教学目标：先玩明白，再解释代码

让学生完成四件事：预测一段短代码会怎样运行；通过游戏观察验证预测；修改一个规则并说明影响；用正常情况和边界情况检查自己的修改。

不要把“看过整个项目”当作学习成果。碰撞和画面系统可以先作为老师准备好的积木，学生仍然能够理解真实游戏里的变量、判断、函数、循环、坐标和状态。

| 层级 | 先学什么 | 能做出的成果 | 暂时不要求 |
|---|---|---|---|
| 入门 | 参数、比较、if、函数返回值 | 改比赛时长，判断胜负，解释平局 | 类、向量、透视 |
| 基础 | 坐标、方向、循环、函数调用 | 预测运动方向，理解重置与倒计时 | 反弹公式和渲染 |
| 进阶 | 状态、冷却、边界、测试用例 | 解释一次按键只踢一次、整球越线、暂停与重开区别 | 指数积分、复杂碰撞法向量 |
| 拓展 | 二维向量、规则设计 | 解释斜跑等速，设计靶区或简单电脑行为 | 完整游戏引擎 |

## 二、精选真实代码片段

下面代码是当前项目的真实摘录。用“文件 + 函数名”定位，行号仅辅助，因为后续修改会使行号移动。

`winner`、`remaining_time` 可以在项目环境中单独调用，不需要打开游戏窗口。含 `self` 的方法和依赖 `pygame` 的片段需要原有对象/环境，不应直接粘贴到空文件后要求初学者运行。

### S01 · 参数就是游戏规则的入口

来源：`settings.py`。原文件的非连续行摘录：

```python
MATCH_SECONDS = 90
PLAYER_SPEED = 280.0
KICK_SPEED = 740.0
KICK_COOLDOWN = 0.30
```

- 学习点：变量/常量命名、数字、单位和“数据影响行为”。
- 可观察实验：只把比赛时长改为 60，先预测什么改变、什么不改变，再试玩。
- 升华：改一个参数不一定能改变所有相关行为。例如踢球速度还受 BALL_MAX_SPEED 限制，不能把“参数越大”简单理解为“一定无限更快”。
- 教师约束：先开放时长和跑速等少量参数；暂不随意把 BALL_FRICTION 设为 0，当前公式会除以它；PHYSICS_STEPS 必须为正整数。参数实验使用副本并记录原值。

### S02 · 胜负判断：看懂条件和返回值

来源：`match.py` → `winner`（本轮约第 15 行）。

```python
def winner(red_score, blue_score):
    if red_score > blue_score:
        return '红队获胜！'
    if blue_score > red_score:
        return '蓝队获胜！'
    return '精彩平局！'
```

- 学习点：比较运算、分支顺序、return。
- 可观察活动：用红队领先、蓝队领先、平分三种输入预测结果，再调用函数验证。
- 进一步思考：平局分支为什么不需要再写一遍相等判断？return 后的代码还会执行吗？

### S03 · 倒计时：时间单位与下限

来源：`match.py` → `remaining_time`（本轮约第 23 行）。

```python
def remaining_time(start_time, now):
    return max(0.0, MATCH_SECONDS - (now - start_time) / 1000)
```

- 学习点：毫秒到秒、减法、max 保底。
- 可观察活动：给定开始时间和当前时间，先算经过了几秒，再算剩余时间。
- 进一步思考：为什么不能只用 now？超过比赛时长后为什么显示 0 而不是负数？

### S04 · 按键转换为方向：把事件变成数据

来源：`main.py` → `read_directions`（本轮约第 44 行）。

```python
def read_directions(keys):
    return [
        (int(keys[pygame.K_d]) - int(keys[pygame.K_a]),
         int(keys[pygame.K_s]) - int(keys[pygame.K_w])),
        (int(keys[pygame.K_RIGHT]) - int(keys[pygame.K_LEFT]),
         int(keys[pygame.K_DOWN]) - int(keys[pygame.K_UP])),
    ]
```

- 学习点：布尔值转整数、正负数、相反方向抵消。
- 可观察活动：只观察红队左右输入，列出 D/A 四种真假组合，对应 1、-1 或 0。
- 进一步思考：同时按左右为什么不是两个方向先后移动？先讨论方向，再讨论速度。

### S05 · 重置：循环和函数复用

来源：`main.py` → `reset_field`（本轮约第 16 行）。

```python
def reset_field(players, ball):
    for player in players:
        player.reset()
    ball.reset()
```

- 学习点：列表、for、对不同对象调用同名方法。
- 可观察活动：跟踪两位球员各调用几次 reset，球又调用几次。
- 进一步思考：reset_field 只重置场上对象，不负责清比分；比分由 main.run 在新比赛/回首页分支清零。函数名不能代替阅读函数内容。

### S06 · 位置更新：速度乘时间

来源：`player.py` → `Player.update`（本轮约第 49 行）。

这里只摘取方法中的两行位移更新。上下文已提供球员的速度与本帧时间 dt：

```python
self.x += self.vx * dt
self.y += self.vy * dt
```

- 学习点：坐标、速度、dt、增量赋值、对象状态。
- 可观察活动：课堂先只看 self.x += self.vx * dt 与 self.y += self.vy * dt；给定速度和 dt，用纸笔追踪两次更新。
- 进一步思考：同样的一秒分成不同帧数，位移为什么应接近相同？说明本实验忽略碰撞、边界和输入变化。

### S07 · 踢球冷却：能否行动也是一个状态

来源：`player.py` → `Player.kick`（本轮约第 36 行）。

```python
def kick(self, direction=None):
    if direction is not None:
        self.aim_at(direction)
    if self.cooldown <= 0:
        self.kick_direction = self.aim
        self.kick_time = KICK_DURATION
        self.cooldown = KICK_COOLDOWN
        self.kick_hit = False
```

- 学习点：条件守卫、布尔标记、计时、记录方向。
- 可观察活动：跟踪一次踢球前后 cooldown、kick_time、kick_hit 如何变化，再观察冷却期间重复按键。
- 进一步思考：冷却防止动作频繁开始；kick_hit 防止同一次动作多次命中，两者用途不同。方法本身不等于踢中了球，真正命中在 collision.try_kick 判断。

### S08 · 完整越线：边界比中心点更重要

来源：`match.py` → `goal_scorer`（本轮约第 5 行）。

```python
def goal_scorer(ball):
    if not GOAL_MIN + ball.radius <= ball.y <= GOAL_MAX - ball.radius:
        return None
    if ball.x + ball.radius < FIELD_LEFT:
        return 'blue'
    if ball.x - ball.radius > FIELD_RIGHT:
        return 'red'
    return None
```

- 学习点：范围判断、严格不等式、提前返回、None。
- 可观察活动：先假设球的前后位置在门口中间，只研究球的左/右边缘和门线。再加入前后范围限制。
- 进一步思考：以右门为例：球半径 16、门线 1180，球心 1196 时左边缘刚好在门线上，尚不计分；1197 才完全越线。球还必须在门口范围内。

### 阅读时的脚手架

S03 的一行倒计时可以在课堂先拆成如下等价写法。这是教学展开版，不是新的生产代码：

```python
elapsed_seconds = (now - start_time) / 1000
remaining = MATCH_SECONDS - elapsed_seconds
return max(0.0, remaining)
```

它属于函数体片段，不可单独放在文件顶层运行。教师应提供完整函数外壳、参数示例，以及 MATCH_SECONDS 的值。

S06 不必一次讲完整方法：先把 aim_at、clamp_to_field 解释为“老师提供的方向/边界积木”，只研究位移两行；进阶时再回到原文件看这些积木如何工作。`self.x` 暂时解释为“这位球员自己的左右位置”。

S04 同样先提取一条左右方向表达式，不要求学生一开始理解整个列表、元组和 Pygame 键盘接口。

## 三、从理解到进阶的课堂路线

以下是可组合的教学单元，不是固定课时要求；可以根据学生基础拆分或合并。

| 单元 | 游戏里的问题 | 代码入口 | 学生活动 | 学习证据 |
|---|---|---|---|---|
| 1：谁赢了 | 比分不同或相同时显示什么 | S01、S02 | 预测、运行三个比分组合、改胜负文案 | 能解释每个分支何时执行 |
| 2：为什么能移动 | 方向键如何变成前后左右位置 | S04、S06 的位移两行 | 填方向表、画坐标、追踪两帧 | 能说出正负方向和速度/时间关系 |
| 3：时间与重开 | 到时怎么结束，重开恢复哪些内容 | S03、S05 | 计算倒计时，列出重置清单 | 能区分重置位置与清空比分 |
| 4：规则与公平 | 为什么不能一直连踢，为什么压线不算进球 | S07、S08 | 跟踪变量、构造边界例子 | 能用具体例子说明规则必要性 |
| 5：设计者挑战 | 如何设计一个训练目标或新结束条件 | 前述函数的组合 | 先写自然语言规则，再写小函数和验证例子 | 能解释“输入—判断—结果”并验证边界 |

每个单元使用“先玩/看现象 → 预测 → 读短代码 → 运行验证 → 改一处 → 解释变化”的顺序。鼓励学生先提出假设，不把读代码变成逐行翻译中文。

## 四、15 题蓝图：5 选择 + 5 判断 + 5 简答

下表规划题目考点、代码参考和评价目标，尚未编写完整题干、选项、正式答案或学生试卷。未来组卷时只选已经教过的内容；进阶考点可替换为同层级基础题。

### 选择题规划（5 题）

| 编号 | 核心考点 | 参考代码 | 出题形式 | 要检验的理解 |
|---|---|---|---|---|
| C1 | 参数与单位 | S01 | 修改 MATCH_SECONDS 后，选择正确的游戏变化 | 区分时长、跑速与帧率 |
| C2 | 分支与返回值 | S02 | 给出一组比分，预测返回结果 | 正确执行条件判断，含平局可能 |
| C3 | 按键抵消 | S04 | 给出两个按键的真假值，预测横向方向值 | True/False、减法和正负方向 |
| C4 | 一步位移 | S06 的位移两行 | 提供 x、vx、dt，选择更新后的 x；明确无碰撞 | 速度乘时间，而不是直接加速度值 |
| C5 | 状态与执行条件 | main.run 的 state 判断，届时只摘短段 | 根据 start/playing/finished 状态选择是否更新运动 | 画面显示和规则执行并非总同时发生 |

干扰项来自常见误解，不用生僻语法或含糊措辞制造难度；每题只有一个明确正确项。

### 判断题规划（5 题）

| 编号 | 核心考点 | 参考代码 | 出题方向 | 要求的证据 |
|---|---|---|---|---|
| T1 | 单位换算 | S03 | 毫秒与秒能否直接相减 | 指出 /1000 的作用 |
| T2 | 倒计时下限 | S03 | 比赛超时后的函数返回值 | 结合 max 说明，区分原始差值和返回值 |
| T3 | 一次动作与一次命中 | S07、collision.try_kick 的标志判断 | 一次踢球动作能否每帧重复命中 | 区分 kick_time 与 kick_hit |
| T4 | 重置职责 | S05 与 main.run 清分片段 | reset_field 是否直接清空比分 | 指出函数内部没有比分赋值 |
| T5 | 画面与规则 | field.project 和 match.goal_scorer 的简化对照 | 只改绘图大小是否自动改变物理球半径 | 说明世界坐标/物理参数与显示的区别；作为进阶题 |

每题除了判断，还要求一句理由；错误陈述让学生给出最小修正，降低猜对的偶然性。

### 简答题规划（5 题）

| 编号 | 核心考点 | 参考代码 | 任务方向 | 评价重点 |
|---|---|---|---|---|
| Q1 | 测试意识 | S02 | 为胜负函数设计红胜、蓝胜、平局输入并说明结果 | 覆盖三种分支，输入和预期一致 |
| Q2 | 变量追踪 | S06 的位移两行 | 追踪两次位置更新，解释 dt 的作用 | 过程正确，能说明时间单位和前提 |
| Q3 | 可读性 | S03 | 把一行倒计时拆成可读步骤，解释不显示负数的原因 | 含义等价、变量命名清楚、解释有因果 |
| Q4 | 规则设计 | S07 | 解释冷却的用途，并设计比较两个冷却值的试玩方法 | 不只说“更快更好”，能讨论公平、按键时机和验证 |
| Q5 | 边界推理 | S08 | 用球心、半径和门线解释完整越线，设计压线与越线例子 | 使用球边缘、注意严格不等式、记得门口范围条件 |

不要以背诵整段代码作为主要评分依据。可以接受文字、表格、坐标图或短代码表达，只要逻辑和证据清楚。

### 可选评分方案

选择题每题 4 分，共 20 分；判断题每题 4 分，其中判断 2 分、解释/修正 2 分，共 20 分；简答每题 12 分，共 60 分。简答可分为逻辑正确、过程证据、解释清楚各 4 分。合计 100 分，也可改为不计分的课堂讨论。

## 五、未来如何交付题目，让学生能参考代码

未来正式材料建议分开保存：

- 学生题目：只保留题干、必要短代码、输入假设和作答区。
- 学生参考代码卡：按 S01–S08 编号，每段标明源文件、函数名、必要变量含义和单位。给完整项目供感兴趣的学生继续阅读。
- 教师讲解：答案、推演过程、常见误解、追问与分层提示。
- 学生练习副本：只在明确的 TODO 区域留白，默认骨架仍可启动，不直接覆盖教师可玩版本。

题目通过“参考 S03 / match.py 的 remaining_time”定位，不要求学生在完整主循环中盲找，也不只靠容易失效的行号。正式出卷前重新从当前版本抽取代码，检查题干假设、选项和答案是否仍成立。

## 六、后续代码维护应保留的教学价值

| 应保留 | 原因 | 应避免 |
|---|---|---|
| winner、remaining_time 等职责单一的规则函数 | 输入输出明确，可脱离画面验证 | 将规则塞进 UI 绘制函数 |
| MATCH_SECONDS、PLAYER_SPEED 等有含义的名字 | 学生能把参数与现象对应起来 | 为了短而改成难懂缩写或散落魔法数字 |
| 直接的 if、for 和明确状态名 | 能画流程、跟踪执行 | 在学习入口过度使用回调、元编程和复杂继承 |
| 重置逻辑的职责边界 | 可讨论“重置哪些，不重置哪些” | 把所有状态清理揉成一个不透明的大函数 |
| 显式的单位和边界含义 | 方便计算和检查 | 只写“修复问题”而不说明为何限制范围 |
| 可复现的短实验 | 学生能验证自己的推理 | 一次改多个参数，无法判断结果来自哪里 |

不是把所有工程代码强行改写成初学者风格。更合适的是保留可读的规则入口，教学材料为复杂方法提供逐步展开版；底层绘图缓存、素材加载和稳定碰撞仍可保持必要复杂度。

后续新增训练或 AI 功能时，优先提供小而明确的规则函数，给学生一个真正能改变游戏的修改点，而不是让学生只改颜色和字符串。

## 七、哪些内容先由教师提供

scenery.py 的网格与静态缓存、resources.py 的字体与资源兼容、collision.py 的反弹法向量和去重叠、ball.py 的指数摩擦积分、main.py 的鼠标按钮事件细节，均不适合作为第一轮必学内容。

斜向归一化可以作为进阶选学：先用格子纸观察 (1, 0) 与 (1, 1) 的长度不同，再讨论公平跑速，最后看 Player.aim_at；不要求未学相关数学的孩子先推导平方根。

先以 S01–S03 做一次短课堂试讲，观察学生能否预测输出、解释平局和时间下限；再决定第一套 15 题的难度。之后再制作完整学生题目、教师答案和练习副本。
