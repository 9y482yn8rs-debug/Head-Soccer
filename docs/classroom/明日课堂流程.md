# 2026-10-02 课堂流程（教师）

## 今天课前准备

1. 在学生实际电脑解压学生包，建立 .venv 并启动 main.py；Mac 首次运行必须先试，不能用 Windows 测试代替。
2. 玩简单、中等各一局；确认声音不是教学依赖（本版本不依赖音效）。
3. 学生读《学生使用指南》，教师保留《教师答案与讲解》；不要把整份教师工作目录发给学生。
4. 准备 GitHub 账号与仓库流程；账号和网络问题留到课前处理，若不通，课堂先用解压包完成学习。
5. 保留未修改的学生 ZIP 作为课堂基线。首次导入仓库后保存一条“课堂基线 v1”提交。

## 60 分钟建议安排

| 时间 | 学生做什么 | 教师关注点 |
|---|---|---|
| 0–8 分钟 | 简单与困难各体验一局 | 说出观察到的差异，不急着解释算法 |
| 8–15 分钟 | 找到 ai_settings.py、should_defend | 参数和条件决定行为 |
| 15–28 分钟 | 完成练习 1–5 | 看代码推结果，不背术语 |
| 28–43 分钟 | 练习 6：只改一个参数 | 先预测，再验证；记录不符合预期的现象 |
| 43–53 分钟 | 与 Codex 完成一次小改动和检查 | 学生提出要求，读懂差异；老师把关 |
| 53–60 分钟 | 提交代码、展示变化、提出下一个需求 | 学生解释“为什么改、怎么证明” |

若只有 40 分钟：仓库建立移到课前；练习做 1、2、3、6，其余课后完成。若零基础，先讲变量、数字比较和 and，跳过几何算法。

## 现场可用的小任务提示词

先让学生自己说目标，再参考这一段：

> 我们在做少儿编程课堂演示。请先读 ai_settings.py 和 ai.py，解释 easy 的 reaction 怎么影响电脑决策。仅将简单档 reaction 从 0.65 改成 0.90，保留其他难度、速度和玩法。展示修改前后差异，并运行现有相关检查。不要重构项目或增加新功能。最后用学生能懂的话解释为什么每帧移动和定时决策不冲突。

该提示词是明天的演示任务，今天没有提前改成 0.90。测试通过只代表原功能未发现回归，手感仍要实玩。

## 如果现场出问题

- 安装或网络超过 5 分钟：用教师准备好的可运行环境体验，学生先做纸面推理；以后再完成学生电脑安装。
- 小改动出错：看差异、保存报错，回到已提交的课堂基线或另解压一份原 ZIP；不要覆盖学生未保存的成果。
- AI 比想象弱或强：这正好成为参数实验，记录场景与观察；不要现场重写整个算法。

## 课堂产出

学生能独立启动游戏、解释一个 and 判断、完成一次有预测和观察的参数修改、写一条清楚的提交说明。进阶学生再做练习 7–8。以后可由学生提需求，教师通过同一仓库的分支和 Pull Request 辅助开发。
