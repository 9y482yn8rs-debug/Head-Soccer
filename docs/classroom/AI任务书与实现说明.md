# 单人 AI：任务书与当前实现

版本：2026-10-01，课堂基线 v1。今天先交付可玩的基线，明天让学生观察、预测、改一处、验证；现场演示只做小改动，不从零搭建整套电脑对手。

## 已完成的范围

首页支持单人对电脑、本地双人；单人红队由学生控制，蓝队由电脑控制。三档可鼠标或键盘选择，重新开局保留选择。沿用当前 B 方案球场、平面运动和八方向踢球，不增加跳跃。

规则型 AI 无需训练或联网。ai.py 只返回移动方向和踢球意图；main.py 把意图交给 Player 和现有碰撞系统。电脑不能直接移动足球、隔空射门或绕过冷却。

| 参数/行为 | 简单 | 中等 | 困难 |
|---|---:|---:|---:|
| 决策间隔 reaction（秒） | 0.65 | 0.28 | 0.12 |
| 速度比例 speed_ratio | 0.52 | 0.82 | 1.00 |
| 最短射门意图间隔（秒） | 1.10 | 0.55 | 0.32 |
| 远球预测时长（秒） | 0 | 0.10 | 0.24 |
| 主动回防 | 否 | 是 | 是 |
| 斜向射门 | 否 | 是 | 是 |
| 射门前主动检查挡球者 | 否 | 否 | 是 |

简单档每 4 秒有约 1.1 秒的思考停顿。简单和中等重复受阻若干次后也会换路线，避免永久卡住；困难档会提前检查。贴边球可借墙反弹回到场内。这些都是运行规则，没有指定真人输赢。

## 决策顺序

1. 检查是否有通向球门的射门方向；困难同时检查对手阻挡。
2. 足够靠近、站位合适且冷却结束才输出踢球意图。
3. 来球朝己方门且需拦截时，中等/困难选择回防位置。
4. 其余情况绕到球后，接近球；角度不合适就带球调整纵向位置。
5. 每帧沿已有目标移动，到下一次决策时再观察；进球后清空旧目标与计时器。

AIController 内部状态：wait 等待、circle 绕行、approach 接近、dribble 带球、defend 回防、shoot 射门。它们便于教师调试，不要求初学者全部掌握。

## 验收与边界

- 原有本地双人、计时、进球、重开流程要继续通过测试。
- 三档在中场、上下边线、站错侧、正前方受阻场景都应在 35 秒内完成进攻。
- 中等与困难对固定快速来球场景应能拦截并继续进攻。
- 首页不运行 AI，单人蓝队不受第二套键盘控制。
- tools/check_ai.py 输出 18 组固定场景；tests/test_ai.py 检查行为和模式流程。

固定场景可以发现卡住和逻辑错误，不能证明学生胜率。三档目前是首轮参数标定；“随便就赢”和“有挑战”需要学生实际体验后调整。先各玩两局，再决定简单是否继续减速或加长停顿；不要同时改速度和反应。

## 明天适合展示的下一步

让学生提出“简单档应该再慢一点反应”的需求，只改 ai_settings.py 中 easy 的 reaction：0.65 → 0.90。预测、保存、重启、体验、记录、提交；保留其他档与物理规则。后续再做训练模式、状态可视化或 AI 难度调优。
