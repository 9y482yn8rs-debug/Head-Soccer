# 哪些提交到 GitHub，哪些留在本机

学生仓库首次导入请使用最新学生 ZIP 中的内容。不要把 ZIP 文件本身上传，也不要把整个教师工作目录复制过去。以后双方在克隆目录内持续修改和同步。

## 应该提交

| 内容 | 原因 |
|---|---|
| 根目录 Python 文件、requirements.txt | 克隆后可安装依赖并运行 |
| README.md、.gitignore、.gitattributes | 仓库介绍、忽略规则、跨平台文本规范 |
| assets/images 中的运行图片 | 代码只引用文件名，缺图会无法启动 |
| docs 中学生指南、练习、学习记录、协作教程 | 学习和协作过程属于项目成果 |
| tests 与 tools/check_ai.py | 别人可以验证改动 |
| 学生新写的 practice.py 或练习目录 | 保留学生自己的成长记录 |

以后增加运行素材、新模块或依赖时，也要提交对应文件并更新说明。不要用 *.png、assets/、docs/ 等宽泛规则把必要内容忽略掉。

## 不应该提交

| 内容 | 当前处理 |
|---|---|
| .venv、venv、__pycache__、pyc | .gitignore 自动忽略，各电脑自行生成 |
| deliverables、build、dist | 自动忽略，属于生成的交付结果 |
| 日志、测试缓存、覆盖率报告 | 自动忽略 |
| .idea、.vscode、系统临时文件 | 默认忽略本机配置；以后需要共享编辑器配置时再明确调整 |
| .env 与本机私有配置 | 默认忽略；当前游戏不需要账号密钥 |
| 教师答案、历史图稿、制作源图 | 学生包按白名单排除；教师工作目录仍保留 |

教师文档和历史设计素材没有被全局忽略：教师如果另建自己的资料仓库，仍可以保存它们。学生仓库依靠精简交付包控制范围，不依靠删除教师资料。

.gitignore 只作用于尚未跟踪的文件，不会自动移除已经提交的文件。[Git 官方说明](https://git-scm.com/docs/gitignore)

## 每次提交前做这五步

1. 确认正在编辑 GitHub Desktop 所显示的仓库目录；先 Fetch/Pull 同步。
2. 查看 Changes，确认没有环境目录、压缩包、私人文件；图片等必要新文件不能漏选。
3. 阅读差异，确认只包含本次任务；运行游戏。改动玩法或 AI 时，再运行 README 中的检查命令。
4. 写明实际改动，例如“调慢简单电脑反应并记录两局体验”，然后 Commit。
5. Push origin；到仓库网页确认新提交出现。仅 Commit 尚未上传。

GitHub 仓库里保留可修改的源码；交付 ZIP 留在本机，需要共享版本下载时再作为 Release 附件发布，不必反复提交进源码历史。[GitHub 大文件与发布分发说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)

## 如果以前已经误提交

在教师协助下，先确认误提交的是哪个具体文件或目录，再只对该路径执行 `git rm --cached 文件路径`（目录加 -r）。这会停止跟踪并保留本地文件；检查差异后提交。不要直接对整个项目执行清理命令。

这不会抹掉旧提交里的文件。对于旧历史中的敏感内容，应另行处理，不能仅靠 .gitignore。

## 初次导入的隐藏文件

Mac Finder 默认不显示点开头文件。复制学生包时按 Command+Shift+. 显示隐藏文件，确保 .gitignore 与 .gitattributes 一起复制；Windows 也应检查它们存在。不要复制其他项目的 .git 目录。

## 后续分工

学生：小练习和学习记录，由学生自己提交。教师：较大功能在独立分支完成，学生一起查看差异与试玩，再合并。避免两人同时修改同一份参数文件；发生冲突先比较内容，不用强推覆盖。
