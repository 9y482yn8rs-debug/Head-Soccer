# 大头足球：首版视觉与基础玩法设计方案

> 状态：设计已落实为首个可玩教师版，启动方法见 README.md。下文保留设计规格；实际素材尺寸、复用方式见 assets/README.md。
> 依据：目录中的效果示意图、《教学项目规划与实施步骤》以及教师确认的方向。
> 目标：第一份可展示版本就具备可爱的角色、协调的界面和明显的动作反馈，同时保持 Python + Pygame 代码易读。

## 1. 首版成品定位

一款明亮、轻松的本地双人大头足球游戏。两名孩子风格的 Q 版球员分属红蓝两队，在同一键盘上移动、跳跃和踢球。画面始终完整展示球场。

参考图中的大头小身体、粗描边、鲜明队色、蓝天草地和热闹看台，作为统一美术方向。减少比赛区背景细节，确保孩子能快速看清球、球员和球门。首版只制作两名球员、一座球场，不加入角色选择、AI、蓄力、特殊技能和道具。

分两次交付可运行成果：

- **A：美术与基础可玩版。** 实际素材、开始界面、双人移动与跳跃、踢球和碰撞、基础动效。比分和计时区域预留，未接通时明确显示“练习模式”，不放假倒计时。
- **B：完整比赛版。** 接通 90 秒比赛、进球计分、庆祝与重置、结果面板和重开。

以下同时定义 A、B 的设计，制作时按这个顺序落实。

## 2. 视觉规范

| 项目 | 约定 |
|---|---|
| 设计画布 | 1280 × 720；首版固定窗口，不先开发自适应布局 |
| 美术风格 | 2D 卡通、圆润造型、深蓝粗轮廓、少量柔和阴影 |
| 红队 | 珊瑚红球衣、深棕头发，活泼表情 |
| 蓝队 | 亮蓝球衣、金棕头发，友好自信的表情 |
| 身材 | 头部约占可见角色高度的一半；脚和踢球动作清楚 |
| 主色 | 天空蓝、草地绿；红蓝队色；金黄用于主要按钮和得分强调 |
| UI 文字 | 深蓝正文、浅色面板；重要数字大且清楚 |
| 字体 | 一款具有明确使用许可的中文字体；正式制作时确定文件并记录来源 |
| 文字生成 | 标题、比分、提示和按钮文字用 Pygame 字体绘制，不画死在图片内 |

建议色值：深蓝 `#173454`、红队 `#F45B69`、蓝队 `#329DF2`、金黄 `#FFD35A`、奶白 `#FFF9EA`。色值是起始规范，实际素材搭配后允许小幅调整。

两队同时通过位置、头像和“玩家 1 / 玩家 2”标签区分，不能只靠颜色。保留清晰的白黑足球，避免与草地混在一起。

| 右球门 | 门线 x=1180，开口 y=420～620 | 与左门镜像对应 |

### 3.2 开始界面

复用球场背景，两名角色站在两侧。中央圆角面板展示“大头足球对战”、简短规则和金黄色“开始游戏”按钮。面板下方并排显示两组操作说明。鼠标点击按钮或按空格开始；启动比赛时清除这次开始输入，避免同时触发射门。

### 3.3 进球与结束界面

- 进球：中央出现“红队进球！”或“蓝队进球！”，放大一次后回到正常大小，少量星星散开；约 1 秒后重置角色与足球。
- 结束：背景覆盖半透明深色层，中央浅色面板显示胜者或平局、最终比分、“再来一局”和“返回首页”。
- 重新开始：鼠标点击或按 R；返回首页：点击按钮。比赛中 Esc 返回首页，窗口关闭按钮始终可以退出。
- 按钮反馈：悬停变亮、按下轻微缩小，松开且仍在按钮内才执行；使用普通鼠标事件与矩形判断。

首批共 15 张图片。UI 面板、按钮、椭圆影子、星星和命中线条由程序绘制，减少素材数量，也适合学生修改颜色、大小和持续时间。

### 角色动作一致性

- 每张角色图画布相同；脚底基准固定在源图 (128,232)。显示时统一缩放到 192×192，脚底基准变为 (96,174)。
- 头、身体在各帧的位置应尽量连续；动作可以变化，不能换脸、换衣服或忽大忽小。
- 跑动只有两帧，优先保证稳定、好认；不追求大量帧数。
- 踢球图保留向右伸腿的空间，脚尖不能被裁掉。左右镜像后脚底基准仍应一致。
- 先完成两名角色的站立形象，再基于定稿形象制作动作和头像；每张都要检查，不把生成结果直接当作可用素材。

素材记录文件后续放在 `assets/README.md`，登记用途、实际尺寸、来源/生成方式、许可信息及需要保留的署名。透明底必须是真实 alpha 通道，不能是画在图片里的棋盘格。

## 5. 基础玩法与碰撞约定

### 输入和动作

| 动作 | 玩家1 | 玩家2 | 规则 |
|---|---|---|---|
| 移动 | A / D | 左 / 右方向键 | 按住持续移动，松开停止；同按左右时不移动 |
| 跳跃 | W | 上方向键 | 按下瞬间触发，只有落地才能跳 |
| 踢球 | 空格 | Enter | 按下瞬间触发，可在空中踢；有短冷却，不自动连续射门 |

面向由最后一次非零水平输入决定。首版允许球员相互穿过，避免两人卡住；球员仍可用头和身体撞球。后续若添加球员之间的阻挡，单独作为规则变更。

### 物理参数起点

统一用秒、像素/秒；以 60 FPS 为目标。以下不是已验证手感，开发试玩后再调。

| 参数 | 初始建议 |
|---|---:|
| 球员水平速度 | 300 像素/秒 |
| 重力 | 1400 像素/秒² |
| 跳跃初速度 | -620 像素/秒 |
| 足球半径 | 24 像素 |
| 踢球水平速度 | 面向 × 720 像素/秒 |
| 踢球竖直速度 | -420 像素/秒 |
| 踢球冷却 | 0.30 秒 |
| 踢球有效动作 | 0.16 秒，同一次最多命中一次 |
| 地面反弹系数 | 0.68；低速时停止竖直弹跳 |
| 足球最高速度 | 1000 像素/秒 |

减速、低速停止阈值和碰撞细节由教师版实现并验证。为降低高速穿透风险，先采用少量固定物理子步；遇到帧卡顿时限制参与模拟的 dt。比赛倒计时使用真实经过时间，不因模拟限时变慢。这部分保留为教师基础设施。

### 图片与物理对齐

球员逻辑坐标采用脚底中心 `(x, y)`。绘制 192×192 图片时，左上角为 `(x-96, y-174)`。碰撞先用头部圆与身体矩形组合：头圆心约 `(x,y-119)`、半径40，身体宽52、高64、底边位于 `y`。根据实际素材可见轮廓校准这些值，不用整张透明画布作为碰撞矩形。

踢球区以脚底坐标和面向计算，向前延伸约80像素、高约64像素；碰到球才施加射门速度。动作期间记录“本次是否已踢中”，防止每一帧重复加速。装饰头发和伸出的手不要求逐像素碰撞。

足球图片缩放后，可见球体直径应为48像素；旋转时用旋转后图片的中心对齐逻辑圆心，避免画面抖动。球门图片则按实际门口定位，图片边框不能代替进球线。

### 球门、边界与比赛规则

- 球员身体留在左右门线之间；足球可进入球门。
- 左侧进球：足球右边缘完全越过 x=100；右侧进球：足球左边缘完全越过 x=1180。足球整体还必须处于开口高度范围内。
- 球门开口上方按边界反弹，开口内允许越线。顶部比赛边界建议 y=112，避免足球飞到比分面板里。
- 左门进球给蓝队加分，右门进球给红队加分。进入庆祝状态后停止运动和重复计分。
- 比赛90秒，进球庆祝计入比赛时间。每帧先检查是否到时，再处理新的进球；结束时不追加该帧进球。
- 进球后重置位置、速度、面向、踢球状态；重新比赛另外清零比分和计时。

## 6. 动效实现清单

| 动效 | 首版方法 | 教学复杂度控制 |
|---|---|---|
| 跑动 | 两帧约每0.12秒切换 | 一个累计时间、一个帧编号 |
| 跳跃 | 空中显示跳跃图，落地恢复 | 根据落地状态判断 |
| 踢球 | 触发后显示踢球图约0.16秒 | 优先级：踢球 → 空中 → 跑动 → 站立 |
| 足球转动 | 根据水平位移改变角度 | 角度变量与 rotate；始终从原图旋转 |
| 脚底影子 | 地面椭圆，跳得越高适当缩小 | 普通绘图与有上下限的尺寸计算 |
| 命中反馈 | 命中位置显示短线约0.12秒 | 一个位置、一个剩余时间；只在真实命中时触发 |
| 进球庆祝 | 文字轻微缩放和约12颗星星 | 简单列表、循环和计时；只在B阶段接通 |
| 按钮 | 悬停变亮、按下缩小 | 矩形包含判断和鼠标事件 |

首版不做骨骼动画、粒子编辑器、复杂镜头晃动或通用特效系统。所有动效只影响表现，不改变球速、得分或比赛时间。

## 7. 文件职责与开发顺序

| 文件 | 职责 | 将来适合学生改动的部分 |
|---|---|---|
| `main.py` | 主循环、事件、状态、对象创建与统一重置 | 后期阅读完整流程 |
| `settings.py` | 尺寸、颜色、运动参数、动作持续时间 | 参数实验 |
| `resources.py` | 一次性加载、缩放、镜像素材与字体 | 更换指定图片 |
| `player.py` | 简单 Player 类：数据、动作与图片选择 | 移动、跳跃、动作判断 |
| `ball.py` | 简单 Ball 类：运动、地面反弹与绘制 | 速度或旋转参数 |
| `collision.py` | 球员碰撞、踢球命中和场地边界 | 首轮由教师提供 |
| `ui.py` | 面板、按钮、操作提示与庆祝绘制函数 | 颜色、文字、简单显示条件 |
| `match.py` | 进球与胜负判断等规则函数 | 胜负判断 |

只在用到时创建对应文件。用普通函数和两个简单类即可，不新增继承体系。主循环维护 `start`、`playing`、`goal`、`finished` 四个简单状态；A阶段先使用前两个。

实际制作顺序：

1. 制作背景和两名站立角色，搭配球门、足球、程序 UI，检查一张真实尺寸的场景效果。
2. 固定形象和对齐基准，补齐动作帧、头像；检查透明边缘、帧间一致性和文件命名。
3. 接入移动、跳跃、足球、碰撞与踢球，加入对应动作和命中反馈，形成 A 版。
4. 接通比赛规则、庆祝、结果界面与重开，形成 B 版。
5. 完成试玩、代码导读，再根据教学规划提取任务版。

## 8. 验收与交付要求

### A版：好看且能操作

- 提供可启动项目、安装运行说明、15张实际素材及其记录、开始和比赛画面截图。
- 同一画面中素材风格一致，角色可爱；足球、脚底、球门和界面文字清楚。
- 透明图片无背景残留、裁边；动作切换不换脸、不跳位；左右镜像后依然对齐。
- 两人能移动、跳跃、踢球；球能落地和反弹；动作与实际命中一致。
- 角色和球不会明显穿地、卡在边界或连续异常弹飞；常用双人按键组合在实际键盘上可用。
- 未接通比赛规则的部分显示练习状态；动效不能代替玩法验证。

### B版：完整一局

- 一局能开始、进球、暂停庆祝、恢复、到时结束，并可重开或返回首页。
- 左右门、门口高球、完全越线、平局和到时边界情况符合规则；一次进球只计一次。
- 重开后所有临时状态恢复；按钮和键盘快捷操作都有效。
- 连续试玩数局，并在目标教学电脑上检查流畅度与文字显示。
- 对纯规则函数做少量必要检查；画面、动效和操作手感通过实际运行验收，不用大量机械测试替代试玩。
