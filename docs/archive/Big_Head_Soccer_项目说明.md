# Big Head Soccer｜项目说明与阶段 1 开发任务

> Python + Pygame · 2D 横版双人大头足球 · 教学项目  
> 使用方法：把本文件放在项目根目录，以 `@Big_Head_Soccer_项目说明.md` 引用，并请 Codex 仅执行文末的「当前开发任务」。

## 1. 项目目标

做一款能持续开发、可供学生参与的小型足球游戏。教师与 Codex 搭建可玩的基础框架，学生以后逐步开发射门效果、AI、技能与道具。代码应容易阅读，按实际需要拆分模块；优先调整操作手感，再制作正式美术。未来可整理为可试玩、可分享的作品。

## 2. 游戏设定

| 项目 | 初始设定 |
|---|---|
| 类型 | 固定视角的 2D 横版 1v1 足球 |
| 技术 | Python + Pygame |
| 窗口、帧率 | 1280 × 720，目标 60 FPS |
| 模式 | 先做本地双人；之后增加单人对电脑 |
| 比赛时间 | 90 秒（阶段 2 实现） |
| 结果 | 时间结束后按进球数判断胜负或平局（阶段 2 实现） |
| 操作 | 左右移动、跳跃、踢球；以后增加技能 |
| 美术 | 先用简单图形表现大头角色、球场和足球 |

球场完整显示在窗口中，左右各一座球门。顶部计分板和倒计时留待阶段 2。画面尺寸与物理碰撞范围分开设计，便于今后换角色素材。

| 功能 | 玩家 1 | 玩家 2 |
|---|---|---|
| 左右移动 | A / D | ← / → |
| 跳跃 | W | ↑ |
| 踢球 | Space | Enter |
| 预留技能 | F | 右 Shift |

## 3. 核心机制

**球员：** 支持水平移动、重力、跳跃、落地和朝向；不穿越球场边界。头部和身体可撞球。踢球键只在脚附近的短暂有效区域施加向前的射门速度。

**足球：** 有位置、速度、半径、重力、反弹、速度衰减与合理的速度上限；与地面、球员及有效边界碰撞。优先保证稳定、有趣的手感，无须模拟真实足球物理。

**比赛（阶段 2）：** 球完整越过球门线且处于球门有效高度时进球；每次仅计分一次。短暂停顿后重置角色与球，更新比分、倒计时和比赛结果。

**电脑对手（阶段 3）：** 根据球的位置和运动趋势追球、防守、跳跃和踢球，设置反应间隔。玩家和电脑共用同一个球员行为实现，输入指令来源不同。

## 4. 代码结构建议

以下是逐步扩展的方向，不要求阶段 1 一次建完：

```text
big_head_soccer/
├── main.py                  # 入口
├── settings.py              # 可调整参数
├── game.py                  # 循环、事件、场景与绘制
├── entities/
│   ├── player.py            # 球员
│   └── ball.py              # 足球
├── systems/
│   ├── physics.py           # 物理和碰撞
│   ├── match.py             # 后续：进球、计时、比分
│   └── controls.py          # 后续：输入映射
├── ai/
│   └── opponent.py          # 后续：电脑球员
├── features/
│   ├── skills.py            # 后续：技能
│   └── powerups.py          # 后续：道具
├── assets/
│   ├── images/
│   ├── sounds/
│   └── fonts/
└── README.md
```

阶段 1 只创建必要文件。核心职责：Game 组织运行；Player 管理球员状态与动作；Ball 管理球运动；碰撞逻辑集中管理或保持清晰边界。不要为尚未实现的功能建空壳。以后为学生的功能提供小而明确的函数或模块接口，避免每加一个技能就改动整个游戏。

## 5. 分阶段开发与验收

| 阶段 | 交付内容 | 验收要点 |
|---|---|---|
| 1 基础原型 | 球场、双方角色、足球、移动、跳跃、踢球、基础碰撞 | 两人能控制角色，球会落下、反弹、被碰撞和踢动，物体不穿地 |
| 2 完整比赛 | 球门判定、比分、90 秒计时、开球重置、开始与结束画面 | 可进行一场完整比赛，进球只计一次，结果正确 |
| 3 单人模式 | 电脑追球、防守、跳跃、踢球；单双人切换 | 一个人能与电脑完成比赛 |
| 4 画面与手感 | 卡通大头角色、场地、动画、音效、反馈与参数调校 | 其他人可直接试玩，操作流畅 |
| 5 学生基础任务 | 蓄力射门、随机射门、连续进球奖励、难度选项 | 每项功能可单独开发、测试和展示 |
| 6 特殊技能 | 统一触发与冷却；火焰射门、冻结球、超级跳跃、冲刺 | 学生可增加独立技能 |
| 7 道具和模式 | 巨型球、小球门、低重力、随机球属性 | 道具能明显改变比赛玩法 |
| 8 完整作品 | 菜单、角色选择、设置、成绩、打包 | 可分享试玩，并考虑在 itch.io 展示 |

每个阶段完成后试玩，再决定下阶段的细节；上述参数和任务可以随操作手感、学生水平调整。

## 6. 学生参与方式

教师和 Codex 先负责窗口、主循环、输入、物理、碰撞、角色和比赛基础机制。学生根据能力参与可观察、可展示的功能。

| 任务 | 可练习内容 | 可见效果 |
|---|---|---|
| 蓄力射门 | 数值增加、上限、函数 | 长按显示力度条，松开后射门 |
| 随机射门 | 随机数、速度计算 | 球速或角度小幅变化 |
| 连续进球奖励 | 计数、条件判断 | 连续进球触发庆祝 |
| AI 难度 | 参数与条件逻辑 | 反应间隔、速度及踢球时机变化 |
| 冻结球 / 超级跳跃 | 状态、计时和恢复 | 短时特殊能力 |
| 火焰射门 / 冲刺 | 状态、速度、冷却、特效 | 明显的技能反馈 |
| 巨型球 / 小球门 / 低重力 | 参数、碰撞范围和规则 | 不同比赛条件 |

例如蓄力射门：底层先提供输入检测、球的受力、碰撞与力度条绘制，学生实现 `update_kick_power(power, charging, dt)` 中的增长、封顶和松开重置逻辑。学生能力提升后，可独立负责整个技能文件或新玩法，而非只填写函数。
